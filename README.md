# 온디바이스 AI 기반 트래킹 순찰 로봇

> 영상 분석, STM32 구동부, Flutter 관제 앱을 연결한 팀 프로젝트입니다.

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 기간·인원 | 2026.05.11~2026.05.21 · 7명 |
| 목표 | 이상 행동 감지 결과를 로봇 추적·관제 흐름에 연결 |
| 기술 | Raspberry Pi 5, STM32F407, Flutter, Bluetooth Classic |
| 상태 | 시연 완료 · 오탐과 성능 정량 검증 과제 남음 |

## 2. 팀 전체 구성

Raspberry Pi에서 영상 분석 결과를 만들고 STM32가 모터·센서를 제어하며, Flutter 앱에서 상태 확인과 수동 조종을 합니다. 팀 전체에는 AI 모델, 펌웨어 제어, 센서 전처리, 모니터링 도구가 포함됩니다.

## 3. 내 담당과 코드 위치

| 담당 기능 | 실제 수행 범위 | 코드 |
| --- | --- | --- |
| 시스템 연결 구조 | Raspberry Pi–STM32–앱 사이 데이터·제어 흐름 설계 | [프로젝트 구성](.) |
| STM32 펌웨어 | 펌웨어 및 통신 인터페이스 개발 | [firmware](firmware) |
| Flutter 관제 앱 | 상태 수신, 수동 조종, PID 게인값 설정·전송 UI | [app/lib/main.dart](app/lib/main.dart) |

AI 모델 학습, 펌웨어 Bluetooth 제어 인터페이스의 일부, 모터 PID 제어는 다른 팀원 담당입니다. 폴더 전체를 제 개인 코드로 소개하지 않습니다.

## 4. 문제 해결 과정

- **문제:** 주행 중 PID 게인을 빠르게 조정하고 상태를 확인할 화면이 필요했습니다.
- **조치:** 앱에서 게인값을 바꾸어 전송하고 Bluetooth로 상태를 받는 기능을 만들었습니다.
- **확인 범위:** 기능 시연은 했지만 게인 조정 전후의 주행 편차를 같은 조건에서 정량 비교한 자료는 없습니다.

## 5. 결과와 남은 문제

팀 시연에서 낙상·위험 행동 분류와 추적 동작을 확인했습니다. 일반 손 흔들기 등에도 위험 행동으로 분류되는 오탐이 있었고, 정확도와 주행 성능의 정량 평가는 부족합니다. 팀 전체 기능을 개인 성과로 합치지 않습니다.
